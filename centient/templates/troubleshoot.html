🛠️ Troubleshooting Guide

Common issues and solutions for CentienC. If your problem isn't listed here, open an issue on GitHub or email me@joshuagoth.com.

SSH & Connectivity
🔐 SSH: "Permission denied (publickey)" or "Permission denied (password)" SSH ▶

This is the most common SSH error. It almost always means one of two things:

1
The server requires key auth, not password. Many VPS/cloud servers disable password authentication by default (PasswordAuthentication no in /etc/ssh/sshd_config). You must use an SSH key even if the password field looks correct.
2
Generate a key from the dashboard. Open the server edit form → find the SSH Key Path field → click 🔑 Generate Key. This creates an ed25519 keypair and shows you the public key.
3
Add the public key to your remote server. SSH into the target server and run:
echo 'your-public-key-here' >> ~/.ssh/authorized_keys chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
4
Test the connection. In the server edit form, click 🔌 Test SSH. If it returns a green ✅ response, SSH is working.
💡 You do not need to type a path manually — the Generate Key button auto-fills it. The path is where the key lives on the CentienC server, not your local machine.
🚫 SSH: "Connection refused" on port 22 Connection ▶

The target machine is reachable but nothing is listening on that port.

1
Check the SSH port. Some servers run SSH on a custom port (e.g. 2222). Edit the server and set the correct SSH Port.
2
Is SSH running on the target? Run systemctl status sshd on the target machine. If it's stopped, start it with systemctl start sshd.
3
Check firewall rules. Ensure port 22 (or the custom port) is open:
ufw allow 22/tcp # Debian/Ubuntu firewall-cmd --add-port=22/tcp --permanent # RHEL/Fedora
⏱️ SSH: "Timed out" or "No route to host" Connection ▶

The CentienC server can't reach the target host at all.

1
Verify the hostname/IP. Make sure you typed the correct IP address or hostname. If using a domain name, check that DNS resolves correctly.
2
Check network routing. CentienC must be able to reach the target. If the target is on an internal network (e.g. 192.168.x.x), make sure CentienC is on the same LAN or VPN.
3
Check if the server is actually up. Ping the IP from the CentienC machine's network — if ping also fails, the machine is off or unreachable.
🔑 SSH key not found — "private key file does not exist" SSH ▶

The SSH Key Path you entered doesn't point to a real file on the CentienC server.

1
Use the Generate Key button instead of typing a path manually. Open the server edit form and click 🔑 Generate Key — it creates the key and auto-fills the correct path.
2
If you have an existing key, verify the path on the CentienC server:
ls -la ~/.ssh/id_*
Common default path: /var/lib/centienc/.ssh/id_ed25519
3
Permissions matter. The key must be readable by the CentienC service user (centienc). If the file is in /root/.ssh/, CentienC may not be able to read it. Move or copy it to /var/lib/centienc/.ssh/.
The CentienC service runs as a limited user (centienc), not as root. Keys stored in /root/.ssh/ are not accessible to this user.
🛡️ SSH fails with "Permission denied: /root/.ssh/id_ed25519" SSH ▶

The CentienC service runs as the centienc system user, not as root. If the SSH key path points to /root/.ssh/, the service user cannot read it and all SSH-dependent features (metrics, log reading, auto-detect) will fail.

⚠️ Symptom: errors in journalctl -u centienc like PermissionError: [Errno 13] Permission denied: '/root/.ssh/id_ed25519'
1
Use the correct key location. Keys for CentienC should live in /var/lib/centienc/.ssh/ which is owned by the centienc user. The Setup Wizard's 🔑 Generate Key button creates the key there automatically.
2
If you already have a key in /root/.ssh/, copy it to the right place:
mkdir -p /var/lib/centienc/.ssh cp /root/.ssh/id_ed25519 /var/lib/centienc/.ssh/id_ed25519 cp /root/.ssh/id_ed25519.pub /var/lib/centienc/.ssh/id_ed25519.pub chown -R centienc:centienc /var/lib/centienc/.ssh chmod 700 /var/lib/centienc/.ssh && chmod 600 /var/lib/centienc/.ssh/id_ed25519
3
Update the key path in Admin. Edit the server → set SSH Key Path to /var/lib/centienc/.ssh/id_ed25519 → save.
4
Test the connection. Click 🔌 Test SSH — a ✅ green response confirms the credentials and permissions are now correct.
Server Status & Metrics
🔴 Server shows "down" but it's definitely up Status ▶

CentienC performs TCP/ICMP pings to check if a server is reachable. A "down" status means the connection attempt failed.

1
Check the hostname/IP. Edit the server and confirm the IP address is correct and reachable from the CentienC machine.
2
Check the port. CentienC tries the SSH port by default. If SSH is blocked or not running, the server will appear down even if it's responding on other ports.
3
Force a re-check. Click the server pill on the dashboard → click Check Now to trigger an immediate check instead of waiting for the next interval.
4
Increase check interval. If the server has intermittent brief downtime, a short check interval may catch those momentary blips. Adjust in Admin → Servers.
📊 CPU / memory / disk metrics not showing or stuck at 0 Metrics ▶

Rich system metrics are collected over SSH. If SSH is not configured or failing, metrics will be empty.

1
Confirm SSH credentials are set. Edit the server — the SSH Username field must be filled in, and either an SSH Key Path or SSH Password must be provided.
2
Test SSH. Click 🔌 Test SSH in the server edit form. A ✅ result means SSH is working and metrics should start appearing within the next check cycle.
3
Enable System Metrics. In the server edit form, make sure System Metrics is checked under Monitoring Features.
4
Wait one check cycle. Metrics are collected on the check interval (default 60s). After fixing credentials, wait a cycle for data to populate.
🌐 Website shows as "down" but I can access it in my browser Websites ▶

CentienC checks websites from the server it's running on, not your browser's location.

1
Network difference. Your browser may be on a different network than the CentienC server. If the site is on an internal network, the CentienC server must also be on that network to reach it.
2
Check the expected status code. If the site redirects (301/302) but you have Expected Status set to 200, the check will fail. Set it to the actual response code, or enable Follow Redirects.
3
SSL certificate errors. If the site has an invalid or self-signed cert, CentienC will report an error unless you disable Verify SSL in the website settings.
Website Analytics & Live Traffic Feed
🔢 Live traffic drilldown shows 0 requests or "No traffic found" Analytics ▶

The live traffic feed reads your web server's access log in real time. Zero results usually means one of the following:

1
The log path is wrong. The most common cause — see the next card for details on how to fix it.
2
No recent traffic. The feed searches the last 30 minutes by default. If the site has genuinely had no visitors in that window, the result will be empty. Try opening the site in your browser and refreshing the drilldown.
3
The website isn't linked to a server. Open Admin → Websites → edit the website. The Server field must point to a configured server with working SSH. Without a server link, CentienC can't read its logs.
4
Click on the website card. From the dashboard, clicking the website row/card opens the drilldown. Make sure you're opening the right site.
📂 Log path is set to a project folder, not an access log file Analytics ▶

The Log Path field must point to the nginx (or Apache) access log file — not a directory and not your site's project folder.

Incorrect examples:

/home/deploy/joshuagoth ← website project directory (wrong) /var/www/html/mysite ← document root (wrong) /etc/nginx/sites-available ← config directory (wrong)

Correct examples:

/var/log/nginx/access.log ← global nginx log (most common) /var/log/nginx/joshuagoth.access.log ← per-vhost log /var/log/apache2/access.log ← Apache /var/log/httpd/access_log ← RHEL/CentOS Apache
1
Fix it: Admin → Websites → edit the site → update the Log Path field to the correct .log file path.
2
Not sure of the path? Use the auto-detect feature (see below). Or SSH into the server and run:
ls /var/log/nginx/
3
Per-vhost logs? Check your nginx config with grep -r "access_log" /etc/nginx/ to find the exact file name for each site.
🌐 Traffic data shows for the wrong website / vhost mismatch Analytics ▶

When multiple sites share a single access log (e.g. /var/log/nginx/access.log), CentienC filters entries by matching the Host header against your website's URL. A mismatch means no filtered results.

1
Check the website URL. Open Admin → Websites → edit. The URL should match the Host header your server sends, e.g. https://joshuagoth.com. The www. prefix is stripped automatically during matching.
2
Use the vhost picker. If your server has multiple virtual hosts, click the ↻ Detect Logs button in the website edit form or in the Setup Wizard. It scans the server's nginx config and presents each vhost with its log file — click one to auto-fill the log path.
3
Per-site logs are the cleanest solution. In your nginx vhost config add:
access_log /var/log/nginx/yourdomain.access.log;
Then set that path in CentienC — no host filtering needed.
🔍 How to use auto-detect to find the correct log path Analytics ▶

CentienC can scan your server's nginx configuration over SSH and suggest the correct log file for each virtual host, so you don't have to find paths manually.

1
From the Setup Wizard: on the "Web Server & Log File" step, click ↻ Detect Logs / Virtual Hosts. It queries your server and lists each vhost with its access log path as a clickable card.
2
From Admin → Websites: edit an existing website, choose its linked server, then click the ↻ Detect button next to the log path field.
3
Click a result card to auto-fill the log path. Then save the website to apply.
4
Requires working SSH. Auto-detect runs via SSH so the linked server must have valid SSH credentials configured first.
If auto-detect returns no results, your nginx config may use a non-standard location. Run nginx -T 2>/dev/null | grep access_log on the server to list all configured log paths.
🔒 Live feed fails — "Permission denied reading log file" Permissions ▶

CentienC reads log files over SSH as the configured SSH user. That user must have read access to the log file.

1
Check log file permissions. On the target server run:
ls -l /var/log/nginx/access.log
If it's -rw-r----- and owned by root:adm, your SSH user needs to be in the adm group.
2
Add the SSH user to the adm group:
usermod -aG adm deploy # replace 'deploy' with your SSH user
The user must log out and back in (or reconnect SSH) for the group to take effect.
3
Or grant direct read access:
chmod o+r /var/log/nginx/access.log
Note this makes the log readable by all users on the system.
Installation & Updates
📦 Service won't start after install — "address already in use" Install ▶

Another process is already using the port CentienC needs.

1
Find what's using the port:
ss -tlnp | grep 8000
2
Stop the conflicting process or change CentienC's port in /etc/centienc/config.env by setting PORT=8001, then restart: systemctl restart centienc.
🔄 How do I update CentienC to the latest version? Update ▶

CentienC is installed as a pip package from GitHub. Updating is a one-liner:

/opt/centienc/venv/bin/pip install 'centient @ git+https://github.com/JoshuaMGoth/centienc.git' \ --no-cache-dir --force-reinstall && systemctl restart centienc
Check the 📣 Updates page to see what's new before upgrading.
Mobile & Browser
📱 Dashboard doesn't update on mobile / page looks broken Mobile ▶

CentienC uses WebSockets for real-time updates. On mobile, background tabs can disconnect the WebSocket.

1
Pull to refresh or tap the reload button. CentienC will reconnect and fetch a fresh snapshot.
2
Keep the tab active. When the browser tab is backgrounded on iOS/Android, the WebSocket may disconnect. This is normal — the UI reconnects automatically when you switch back.
3
Use "Add to Home Screen" for the best mobile experience. Open CentienC in Safari/Chrome → share → Add to Home Screen. This gives a full-screen app with better keep-alive behavior.
🍪 Logged out unexpectedly / "Authentication required" error Auth ▶

CentienC uses a JWT stored in a browser cookie. The cookie expires after 24 hours by default.

1
Log back in. Navigate to /login and authenticate. The session will be restored.
2
On mobile, if cookies are being cleared by the browser's privacy settings, add the CentienC URL to your browser's "always allow cookies" list.
